# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A macOS Qt 6 (C++17) tool that trims a Spitfire Audio library (BBC Symphony Orchestra, Eric Whitacre Choir; each described by a profile): the user picks which microphone positions (per section or voice group) to keep, and the tool builds a trimmed copy in a separate destination folder (copying only the enabled `.spitfire` sample files and patching each section `.db` so it lists only files that exist), so the plugin loads faster and uses less disk. Spitfire system facts (settings, library layout, what the app accepts, plugin errors, other products): `docs/SPITFIRE-SYSTEM.md`. Manual checks on a real library: `docs/ACCEPTANCE.md`. Usage: `README.md`; adding a profile: `docs/ADDING-A-PROFILE.md`.

Safety rules that every change must keep:

- The source library is never modified, also via aliases (no files, folders, lock or config): the DBs are opened read-only; the source and destination may not overlap, see `pathsafety.h`; nothing is written to the destination (not even `project.smt`) before those checks pass, and the config is saved only after the executor has taken its lock and passed its probe.
- DB invariant: at every moment each destination `.db` lists only files that exist in the destination.
- Apply is two-phase (1: patch DBs, then delete switched-off mics; 2: copy additions to `<dest>/.smt-staging/`, rename into place, patch DBs last). There is no journal: every apply re-plans from the real source and destination and every step is idempotent, so an interrupted run is resumed by running it again.

## Build & test

Qt is in `~/Qt/6.11.0/macos`, Ninja in `~/Qt/Tools/Ninja`:

```bash
export PATH=$HOME/Qt/Tools/Ninja:$PATH
cmake -S . -B build/dev -G Ninja -DCMAKE_PREFIX_PATH=$HOME/Qt/6.11.0/macos -DCMAKE_BUILD_TYPE=Debug
cmake --build build/dev
export SMT_APP_DATA_DIR=$(mktemp -d)        # see Environment
ctest --test-dir build/dev --output-on-failure
ctest --test-dir build/dev -R tst_plan --output-on-failure   # one test executable
build/dev/tests/tst_plan testName                            # one test function (QtTest)
```

Targets: `corelib` (static lib), `SampleMicTrimmer` (GUI, a standard macOS bundle `build/dev/src/app/Sample Mic Trimmer.app`: `open` it, or run `Contents/MacOS/Sample Mic Trimmer` from a terminal; the profiles are copied into `Contents/Resources/Profiles/`), `cli` (binary `mictrim`), one `tst_*` executable per area under `tests/`, and `copybench` (manual copy-throughput benchmark, not a ctest test). `build/` and `CMakeLists.txt.user` are local artifacts (git-ignored).

CLI: `mictrim -s <source> [-p <dest>] [--profile <id|path.smtprofile>] [--rescan] analyze|plan|apply [-y]` (without `--profile` the profile is suggested from the source folder name, else BBCSO; `bbcso`/`ewc` are accepted short ids). `analyze` needs only `-s`; `plan` and `apply` also need `-p`; `apply` only prints the plan unless `-y`; Ctrl-C cancels an apply between files. Exit 0 ok, 1 refused/failed, 2 usage.

Packaging: an incremental build keeps a stale copy of a deleted profile file inside the built `.app` (profiles are copied by `MACOSX_PACKAGE_LOCATION`), and `cmake --install` would ship it. Delete the `.app` (or `build/dev/src/app/*.app/Contents/Resources/Profiles`) or use a fresh build directory before packaging or installing.

## Architecture

All logic is in `src/corelib` (no GUI). Data flow: scan -> classify -> Plan -> PlanExecutor.

- `fileinfogatherer` + `qfileinfogatherertask` — scan of a directory into `FileInfo`s, entirely on a pool thread (cache read/parse, every stat, cache write) so the GUI thread never does file IO or bulk parsing; results reach `FileInfoGatherer` in batches (`foundFileInfos`, ~2000 files or 50 ms) with `progress(scanned, expected)` (expected = a previous scan's file count, -1 unknown; callers cap the percentage below 100 until `finished`). `setPreloaded()` answers a run from memory without IO. The source scan is cached per directory as a compact binary file `<app data>/ScanCache/<sha1 of the cleaned folder path>.smtcache` (magic `SFMC`, format version, folder, count, one record per file; read and written by the worker, strictly validated: anything damaged, truncated, foreign, another version or with a hostile count is ignored and the folder is scanned again; written after `finished()` through `QSaveFile`; a scan with no section `.db` is not cached; the file count sits in its header; hits touch the file, and files unused for 90 days and the old `*.json` / `sourceDirectoryCache.json` caches are deleted by a worker at start-up). `Core` also keeps the last 3 finished source scans of the session (`mSourceScans`, keyed by the cleaned folder path, same staleness rule as the disk cache) so switching libraries back and forth is instant; destination scans are never reused (always rescanned, Apply waits for them). `Core::rescanSource()` drops only the current folder's cache and session scan and rescans (the GUI's "Rescan source" button, disabled while a scan or an apply runs, and `mictrim --rescan`). `Core::scanStatus()` / `scanStatusChanged()` feed the status text.
- `profile` / `profileregistry` — see "Profiles" below.
- `smt.h/.cpp` — domain model: string `MicSignalGroupKey{mic, group}` and `classify(profile, relPath)`, which classifies a sample file by the mic token before `.spitfire` (e.g. `_TR01`, `_TR01_02`); only tokens the profile lists, under its `samplesDir`, are mics.
- `analysis` — `analyzeLibrary()`: mic positions found in the source DBs, with sizes (read-only).
- `librarydb` — read the `Containers` names of a `.db`; `writePatchedCopy()` writes a patched copy (only `Containers` rows removed).
- `projectconfig` — `<dest>/project.smt`: which mics are enabled (missing file = all enabled).
- `pathsafety` — `checkSourceAndDestination()` (reads only, never writes): refuses any overlap of source and destination by canonical path (symlinks), by file identity (firmlinks) and by mount identity (`statfs` mount source + path below the mount, so a second mount of the same SMB/NFS share such as `/Volumes/Share-1` is caught) and by directory identity across mounts (`stat` inode + birth time on a different device, for a second mount whose mount source is spelled differently). The mount and stat checks are macOS/BSD only and injectable via `pathsafety_testing.h`. They are best-effort (silent when a server reports no stable inode/birth time, e.g. NFSv3 or some Samba/NAS; SMB caching can hide the lock probe; a sub-folder mount with a differently spelled mount source can be missed), so a local-disk destination is the intended use; see "Limits of the alias checks" in `docs/ACCEPTANCE.md`. `resolveDestinationFolder(source, chosen)` (pure string work, used by the GUI's Choose… for the Reduced Mic Installation at choose time only): the picked folder itself if it already has the required name (or the source is no `Spitfire Audio - …` folder), else `chosen/<name>`; the resolved path is what the label and the per-profile settings hold, it is not created at choose time (the executor creates it once the checks pass and removes it again, never the chosen parent, on a refusal before the first step; a destination that does not exist scans as empty), and it still goes through every check (picking the source's own parent resolves to the source: "the destination is the same folder as the source"). The CLI `-p` stays literal. `checkDestinationName()`: for a `Spitfire Audio - <product>` source the destination folder must have the same name (the Spitfire app rejects other names as an invalid library; `Core::buildPlan` refuses). `checkSourceLock()`: the backstop probe the executor runs after taking its lock, looking for that lock as `<source>/.smt.lock` and `<source>/<each trailing part of dest>/.smt.lock`.
- `plan` — `buildPlan()`: pure function from scans + config to a `Plan` of `PlanStep`s (ReplaceDb, DeleteFile, CopyToStaging, MoveIntoPlace; phases 1/2), byte totals and refusals (e.g. not enough free space). Settings files (a non-mic, non-database file whose first path component is exactly `Patches`, `Presets` or `Config`; `isSettingsFile()`) are always copied again, even when the destination has the same size, because Spitfire's Repair rewrites them in place at the same size and they are signed per install: their copy and move steps carry `refresh`, the copier overwrites a staged leftover (`CopyJob::overwrite`), the executor's "already in place" shortcut is skipped, and they never count as already staged. A destination file missing from the source is still never deleted. So a library that has such files always shows a pending "Apply (+X / −0)" (X = their bytes); one without them still says "No changes".
- `copier` — `copyFiles()`: pipelined reader/writer copy to `<dest>.part`, size check, rename; `CopyOptions` (buffer size, concurrency) are the tunables.
- `spitfiresettings` — `repointLibrary(propertiesFile, profile, libraryRoot)`: profile-driven. For every `spitfireEntries` entry of the profile (from its `spitfire.json`) and every key it lists, the key in Spitfire's own `~/Music/Spitfire Audio/Settings/Spitfire.properties` becomes `[libraryRoot/<sub>, ...]` ("" = the folder itself), whatever it pointed at before; entries and keys the profile does not list, and other products, are untouched. A listed entry missing from the file is refused naming it, as is a profile without entries ("does not describe its Spitfire settings entries"), a non-folder target and unparsable JSON; nothing is written then. Backup `.smt-backup` first (the first backup stays the original: an already-correct file is not rewritten), atomic write; no library file is touched. `Core::useLibrary()` (current profile; trimmed = the destination, else the source; refuses a wrongly named destination), CLI `mictrim use source|trimmed -s <src> -p <dest> [--profile ...] [--properties FILE]` (profile from `--profile`, else the source folder name, else BBCSO; no scan runs) and the GUI's "Change current installation location…" button (under the profile picture) use it. Tests always pass a temp properties file; never the user's.
- `planexecutor` — runs a Plan on a worker thread: path checks, then creates the destination, lock file, lock probe, then an optional `prepare` hook (Core saves `project.smt` there), then the steps; a run refused before its first step removes the empty folders it created. Staging dir, cancel between steps/buffers, progress signals.
- Background mode (`Core::setBackgroundWork(true)`, set by the GUI; the CLI and the tests are synchronous): nothing that touches the file system or walks all the files runs on the GUI thread. The destination volume's free space (`refreshFreeSpace`), the project.smt read (`reloadConfiguration`), the completeness derivation (`startDerive`: `scanFinished` is owed once both scans are done and emitted exactly once by `settleScans()` when no configuration read or derivation is pending; a user click during a derivation wins for its key) and the plans (`requestPlan()` → `planReady`, `requestPendingChange()` → `pendingChangeReady`; path checks, lock probe, free space and the plan itself run on a worker from a `PlanSnapshot`) run on pool threads through `runAsync()`/`WorkRelay`; only the latest request of a kind is answered and only while the plan's generation is current (stale answers are dropped, the GUI asks again when its inputs change). `Core::scanning()` is true during scans and this preparing work, `scanStatus().preparing` / `scanStatusText()` say "Preparing…". `startApply` leaves the overlap check to the executor, whose `start()` runs it (then the folder creation, lock and lock probe, all file IO on the calling thread) before it writes anything. The synchronous `buildPlan()`, `pendingChange()` and `loadConfiguration()` remain for the CLI and tests.
- `completeness` — `completeMics()`: pure function giving, per {mic, group}, whether the destination holds every source file of it as a tri-state `Completeness` (Empty / Partial / Complete; same path and size; with an unscanned source: any file of it is Complete). Raw facts, locked mics not forced.
- `planmodel` — list model of plan steps for the GUI.
- `Core` (`corelib.cpp`) — facade (`QObject`) used by both front ends: source/destination paths, scans, config load/save (a corrupt `project.smt` emits `configurationError` and is never overwritten), `buildPlan()`, `startApply()`, free-space/size accounting, signals. `setSelectionFollowsDestination(true)` (GUI only; the CLI and tests default to off, i.e. project.smt / all enabled) makes the in-memory selection follow `completeMics()` of the finished source and destination scans, re-derived on destination, profile, source rescan and after an apply's rescan, never during an apply; the mics stored in `project.smt` are then ignored (the file is still loaded for the profile check) and an empty destination checks only locked mics. A Partial key (interrupted apply, changed sizes) is enabled, so the resume rule holds in the GUI too: partly present = wanted until the user unticks it (shown partly checked via `micCompleteness()` / `micCompletenessChanged`; any `setMicEnabled` makes it a plain box), and Apply completes it instead of deleting it.
- `coreutil.h` — size and progress-line formatting shared by GUI and CLI.

Window layout (`mainwindow.ui`, `MainWindow`; `chooseDestinationFolder()` is what Choose… does with the picked destination): left column = profile pop-up, artwork, then the "Change current installation location…" button (grey during an apply, via `updateProfileControlsEnabled()`); right column = the two folder rows, the matrix, the legend (`MatrixColors::legend()`, swatches in the matrix colours), the footer and Apply. A folder path is plain elided text (full path as tooltip, "No folder chosen" while unset). With no source content (`Core::hasSourceContent()`: no source folder, or a finished scan that found no file) `updateEmptyState()` shows a hint instead of the matrix, legend and footer. Apply is the primary button (`stylePrimaryButton()`) whose text comes from `Core::pendingChange()` (the plan's bytes to copy and to delete) via `applyButtonText()`: "Apply (+X / −Y)", "Apply (update databases)" for a plan with only database rebuilds, "No changes" (disabled) only for a plan without any step, plain "Apply" while a scan runs (Apply is disabled then); `applyEnabled()` also disables it when the plan is refused: the first refusal (in the muted red `Palette::errorMuted`, as is "Needs Z more space"; "Select at least one microphone." in amber) is shown in `applyStatusLabel` (while a scan runs it shows the progress instead, in the muted grey: "Scanning Source… 42%", "… 12,345 files" without a known total, "Scanning Reduced Mic Installation…"), which spans from the table's left edge to the Apply button (the label is Expanding with stretch 1 even when empty; Apply has stretch 0 and a minimum width set once from `applyButtonText(longestPendingChange())`, so neither its text nor the message resizes it), and as its tooltip, never while enabled, scanning, applying or without a source; `updateApplyEnabled()` is the single place that sets it, coalesced to one plan build per event-loop turn. The window title is `mainWindowTitle()` (app name — profile name), set in `rebuildProfileUi()`. `tst_mainwindow` runs the real `MainWindow` offscreen (isolated settings, no downloads).

The GUI headings are "Source Installation" and "Reduced Mic Installation"; their folders are stored per profile in QSettings by `src/app/profilepaths.h` (`Profiles/<escaped id>/SourceDirectory|BackupDirectory`, plus `LastProfile`; the old global keys are read as BBCSO's fallback). `MainWindow` is the only place that picks a profile from a folder name; it always switches explicitly, so Core's own auto-switch stays inactive in the GUI.

`src/app` (Qt Widgets: `MainWindow` with one mic matrix: `MicMatrixModel` (a tree over `Core`: group rows from the profile's family `tab` values, mic rows, a column per section plus the row total; tri-state cells, a click on a partly present cell unticks it; partly present counts as wanted in the row name cell and column heading: fully wanted (everything filled, partly present included) clears all on click; some not filled fills the missing ones; `toggleColumn()`), `MicMatrixView` (the `QTreeView` configured as a table, group rows spanning, whole-cell click; its delegate paints a cell's state as the whole cell's fill: accent-blue tile with dark text = wanted, a damped blue = some wanted (name cell, heading), amber = partly present, dark tile with light text = not wanted, grey = always on, white+dark 2px outline = current cell. The app always runs dark, whatever the macOS appearance: `applyDarkTheme()` (`darktheme.cpp`, called first in `main.cpp`) sets the Fusion style, `QStyleHints::setColorScheme(Dark)` and a palette from the colours in `palette.h`. The matrix colours are constants derived from that palette in ONE place, `micmatrixcolors.h` (`MatrixColors`, not the system palette); `tst_micmatrixview` checks every fill/text pair for WCAG contrast >= 4.5 and the outline >= 3; no checkbox anywhere, because Qt's macOS style draws no item-view check boxes and puts `QStyle` checkbox primitives at the widget's corner) with `MicMatrixHeader` (section name and selected total on a heading, two-tone by the column's state (light = all wanted, mid = some, dark = none), no box; a click toggles the column; `totalTextRightInset()`/`totalTextRightInsetChanged` let the footer row below the matrix (one right-aligned label, "Installation size: X (Y space remaining)" built by `installationSizeText()` in `coreutil.h` from `Core::totalSpaceForSelectedItems()` (selected mics plus always-copied files) and the last `remainingSpaceChanged` value, in `mainwindow.ui` `footerLayout`, filled by `MainWindow::updateFooter()`) end under the Row total numbers), `PlanDialog`, `ConfigErrorNotifier`) and `src/cli/main.cpp` are thin layers over `Core`; keep decisions in corelib.

### Profiles

A `ProductProfile` describes one Spitfire library family (BBCSO, Eric Whitacre Choir). It is data, not code: a macOS bundle `<Name>.smtprofile` (a "package", one file in Finder).

- Layout: `Contents/Info.plist` is the manifest (`CFBundleIdentifier` = the profile id, e.g. `name.mbishop.smtprofile.ewc`; `CFBundleName`; `SMTProfileFormat` = `1`; `SMTProfileLibrary`/`Mics`/`Groups` required and `SMTProfileImages`/`Spitfire`/`Notes` optional, each naming a file in `Contents/Resources/`). Parts: `library.json` (`folderPattern` to suggest the profile, `samplesDir`, `sampleFile` regex with named groups `mic` and optionally `group`), `mics.json` (`mics` `{token, name, family, locked?, note?}`, `families` = GUI group rows (via `tab`), `quickSets`), `groups.json` (BBCSO sections by folder, Whitacre voices by file name), `images.json` (`cache:<plain file name>` in the Spitfire app's image cache `~/Music/Spitfire Audio/Settings/.ImageCache` via `spitfireImageCacheDir()`, `library:` globs into the user's own library, `file:` below `Contents/Resources/`; the first existing source wins), `spitfire.json` (`entries`: `{name, keys: {config|patches|presets|samples: [sub-path, ...]}}`, the entries of Spitfire.properties that belong to the product and the sub-paths each key lists below the library folder, "" = the folder itself; relative, no `..`; without it the profile cannot be used with "Change current installation location…"), `notes.md` (the pop-up tooltip). A profile that does not validate is "invalid: <why>" and cannot be chosen.
- Where they live: the built-ins are `profiles/*.smtprofile` in the source tree. They are compiled in (`:/profiles`, used by the CLI and the tests) and copied into the GUI bundle's `Contents/Resources/Profiles/`; `bundledProfilesDir()` returns that folder when running inside a `.app` and it is read instead of the compiled-in copy. User profiles are the `*.smtprofile` folders in `userProfilesDir()` (`<app data dir>/Profiles`, `$SMT_APP_DATA_DIR` aware; GUI File > Reveal Profiles Folder). A valid user profile with a built-in's id replaces it; an invalid one is a separate entry and never replaces anything. `loadProfiles()` returns the `ProfileEntry` list (`Core::availableProfiles()`); `builtInProfile(kBbcsoProfileId)` is `Core`'s default.
- Rules the engine enforces: only tokens the profile lists are mics (anything else, such as `ERICW_VERB_IR.spitfire` or an unlisted token, is "other": copied, never deleted; `analyze` reports unknown tokens). A `locked` mic (BBCSO Mix 1 `MI01`; Whitacre has none) is always on, in the GUI, the CLI and `project.smt` (`micEnabled()`). The Whitacre profile offers only the nine signals of Spitfire's article (groups Core: Close, Tree, Ambient, Outriggers; Auxiliary: Mid, Gallery; Stereo: Big, Medium, Small); `CL02`-`CL05` and `ST04` are deliberately unlisted, so they are "other": always copied, never shown. Apply needs a mic: `Core::anyMicEnabled()` drives the GUI Apply button (one function, `MainWindow::updateApplyEnabled()`), and in follow mode `buildPlan()` refuses with "Select at least one microphone." (CLI/default mode is unchanged).
- `Core`: `setProfileById()`/`setProfile()` (ignored during an apply), `profileSuggestion()` (from the source folder name, unless the user chose a profile), `profileChanged()` (the GUI matrix model resets and it rebuilds the pop-up, artwork and buttons on it, and `Core` reloads the matching `project.smt`), `applyQuickSet(i)` (the GUI shows one button per `quickSets` entry a profile defines, and hides that row when there are none; the built-ins define none, the user ticks in the matrix; they never touch locked mics and do not save).
- `project.smt` carries `"profile": "<id>"` and `"micSignals": {mic: {group: bool}}`. A file without `profile` is read as BBCSO; a file for another profile than the current one is a `configurationError` and is never overwritten. `project.smt` only records and checks the profile id; the profile is chosen from the source folder name or the pop-up / `--profile`, not from `project.smt`.
- CLI: `--profile <id|alias|path.smtprofile>` (`bbcso`/`ewc` aliases); unknown = exit 2; `analyze`, `plan` and `apply` print the profile first.
- Artwork: the big top-left picture (`ProfileArtwork`, scaled down to 384x384 logical, never enlarged, hidden when there is none) is the profile's `main` image. Built-in `main` order: the official pack shot from the Spitfire app's own image cache (`cache:` sources; read-only, read at display time), then `url:` (the same pack shot on Spitfire's public site, `https://www.spitfireaudio.com/cdn/shop/files/...?width=500`), then nothing: offline with no Spitfire cache the picture slot is simply empty (the `file:` source kind, a file inside the bundle, is still supported for profiles that ship one; list such files in `src/corelib/CMakeLists.txt`). The library's tiny NKS `MST_Artwork.png` is deliberately not in the chain (the `logo` image still uses `MST_Logo.png`). Nothing from Spitfire is copied into the repo, the app or the destination. An image may carry `"credit": "<https page>"`, shown as the artwork's tooltip ("Picture: ...").
- `url:<https URL>` sources: validated at profile load by `isAllowedImageUrl()` (`profile.h`, also for `credit`): scheme `https`, host exactly `www.spitfireaudio.com`, no userinfo or port, path starting with `/` without `..`, at most 300 chars; otherwise the profile is invalid. `resolveProfileImage(profile, name, libraryRoot, cacheDir, urlCacheDir)` (no default for `urlCacheDir`) maps a `url:` source to `<urlCacheDir>/<sha1 hex of the url>` (`imageUrlCacheName()`) if that file exists inside `urlCacheDir`; `profileImageUrlCacheDir()` is `<app data dir>/ImageCache` (honours `SMT_APP_DATA_DIR`); `pendingImageUrls()` lists the not yet downloaded `url:` sources ahead of any source that already resolves. GUI only (not corelib/CLI; only the app links Qt6::Network): `ImageFetcher` (`src/app/imagefetcher.*`) downloads asynchronously, re-checks https + the host allowlist (also for each of at most 3 redirects), aborts after 15 s without data or 30 s in total, max 8 MB, the body must be a PNG or JPEG whose header size is at most 2048x2048 (checked with `QImageReader` before decoding) and decode, then a `QSaveFile` write; `fetch()` never signals for an existing file or an already fetched URL (callers re-run on `fetched`), never retries a failed URL in the session, silent on failure. `MainWindow::updateArtwork()` asks for the pending URLs of `main` and re-runs itself when one arrives. QSettings `DownloadProfileImages` (default on), File > Download Profile Pictures; off = no request is ever made. Tests use a loopback `QTcpServer` with an explicit test-only host/scheme override, never the real network.
- App bundle: `src/app/Info.plist.in` (filled by CMake; `LSMinimumSystemVersion` from the global `CMAKE_OSX_DEPLOYMENT_TARGET` 13.0) exports the UTI `name.mbishop.smtprofile` (conforms to `com.apple.package` and `public.composite-content`, extension `smtprofile`).

## Windows support (experimental: builds and passes all tests in CI on a Windows runner; never used on a real Spitfire setup)

Seams: `winpath.h` (pure string rules for Windows paths, `kIsWindows`), `fsutil.h` (`fs::path` wide-string paths, `replaceFile` = `MoveFileExW` replace-existing with retries, `syncDescriptor`/`syncFile`; `fsutil_win.cpp` is WIN32-only), `pathsafety_win.cpp` (WIN32-only `GetFinalPathNameByHandleW` and `GetFileInformationByHandle` providers, injectable via `pathsafety_testing.h` `setFinalPathProvider`/`setFileIdProvider`; an unobtainable final path refuses), `spitfireSettingsDir()` (the one place that resolves the Spitfire settings folder), `*For(bool windows, ...)` testing functions so the Windows rules run on any host. macOS behaviour must stay unchanged. Unix-only tests use `SMT_UNIX_ONLY()` (`tests/unixonly.h`). Windows packaging needs QtSql and `sqldrivers/qsqlite.dll`. CI: `.github/workflows/build.yml`. Never claim in docs or code that Windows was tested.

## Environment variables

`SMT_SPITFIRE_SETTINGS_DIR` overrides the Spitfire settings folder (any platform; tests and Windows users).


`SMT_APP_DATA_DIR` moves the scan cache and, in the GUI, `QSettings` (to INI files in that dir; `HOME` does not redirect either on macOS). Set it (to a temp dir) for dev/test runs of the app, `smt` and the tests, so the real user cache and settings are never touched; never for real use (including the checks in `docs/ACCEPTANCE.md`).

## Conventions

- Render-check Qt widgets with the real platform style (a throwaway `QT_QPA_PLATFORM=cocoa` harness that grabs the widget); the offscreen style hides macOS differences.
- No raw string literals (`R"(...)"`) in QtTest classes: moc skips them and breaks.
- Tests build fake libraries in `QTemporaryDir`s with `tests/fakelibrary.h`; never touch a real library (e.g. under `/Volumes`) from tests or experiments.
- Test output must be pristine (no stray Qt warnings).
