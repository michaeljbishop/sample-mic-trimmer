# Acceptance checks on the real library

Manual checks for the real network source and local destination. Do NOT set `SMT_APP_DATA_DIR` here (it is only for tests and experiments). Quit the plugin and its host (DAW) before any apply. `smt` below is `build/dev/src/cli/mictrim`; the GUI is the bundle `build/dev/src/app/Sample Mic Trimmer.app` (`open` it).

Never apply into the source folder; use a new, empty destination folder on a local disk. **Name it exactly like the source** (`Spitfire Audio - BBC Symphony Orchestra`) inside a different parent: the Spitfire app's Repair/Locate says "not a valid library" for any other folder name (e.g. `TEST - Spitfire Audio - …`), and `smt` refuses such a destination. Never choose the source folder, a folder inside it, or its parent as destination, including via a second network mount (Share vs Share-1).

**Limits of the alias checks.** (a) The stat-identity check needs the server to report a stable inode and a birth time: it is silent on NFSv3 and on some Samba/NAS setups that invent per-mount inode numbers or report no birth time. (b) Attribute/negative-lookup caching on SMB can hide a lock-file probe hit. (c) A second mount of a sub-folder of the source whose mount source is spelled differently can be missed (the suffix probe cannot know the folder prefix). (d) So never pick the source, a folder inside it or its parent as destination through any mount; a destination on a local disk is the intended use.

1. Copy throughput. `build/dev/tests/copybench <srcDir> <dstDir> 8 3 copier`, then `... qfile`, on a few GB of the real pair (use a subfolder of the source), run each mode separately (warm cache skews "both"), and time `cp -R` on the same data. Expect `copier` within about 10% of `cp` or faster. If not, try other buffer sizes and concurrency (args 3 and 4) and put the best values into the `CopyOptions` defaults in `src/corelib/copier.h` (`bufferBytes`, `concurrency`).
2. Analyze. `mictrim -s <real source> analyze`. Expect every mic position with file count and size, no unknown tokens, and no "missing from disk" entries for an untouched source.
3. Plan. `mictrim -s <src> -p <dest> plan` (changes nothing; expect all steps as copies, no refusals). Then open the GUI, choose the same source and destination, and review the plan dialog: the same steps, byte totals and free space. The source scan is cached: if the source library changed since it was scanned (e.g. a Spitfire update), click "Rescan source" next to the source folder in the GUI (or add `--rescan` to `smt`) before planning.
4. Mix-1-only apply. First measure the baseline: point the plugin at the full source library, load Violins 1 and time it. Then in the GUI untick every cell by hand except Mix 1 (a column heading toggles a whole column) and apply into the new empty destination. (With the CLI instead: `smt` reads the mic selection from `<dest>/project.smt`, which the GUI writes when you apply or that you write yourself; then run `mictrim -s <src> -p <dest> apply -y`.) Point the plugin at `<dest>`, load Violins 1 again and compare with the baseline. Expect it to be faster (the vi-control post reports about 7 s with Mix 1 only).
5. Toggle. Switch one mic off, apply, load Violins 1; switch it on again, apply, load again. Expect the plugin to load at every stage (after each apply, and with the trimmed destination in between).
6. Interrupt. Start `mictrim -s <src> -p <dest> apply -y` on a selection that adds files, press Ctrl-C mid-run (expect a clean "cancelled" exit), check the plugin still loads, then rerun the same command. Expect it to resume (staged files reused) and finish, and the plugin to load.
7. Profile pop-up (GUI). Choose the BBCSO source: the pop-up at the top shows the BBCSO profile. Choose the Whitacre source (`Spitfire Audio - Eric Whitacre Choir`): the pop-up switches to "Eric Whitacre Choir" by itself, the matrix is rebuilt (Whitacre groups and rows, columns Sopranos/Altos/Tenors/Bass/Tutti) and the sizes follow. Switch the pop-up by hand back and forth: matrix, artwork and buttons follow, and a valid `project.smt` of that profile in the destination is loaded; a `project.smt` made for the other profile shows the configuration error and the file is left untouched. During an apply the pop-up is greyed. Hover the pop-up for the profile's notes. File > Reveal Profiles Folder opens (and creates) the user Profiles folder in Finder; drop a copy of a `.smtprofile` there, restart the app, and it is listed; a broken one is listed greyed as "<name> (invalid: why)".
8. No quick buttons (GUI). The header shows only the profile pop-up (no button row and no gap: no built-in profile defines a quick set). Untick every cell by hand (columns headings help; BBCSO keeps its locked Mix 1): on Whitacre Apply is then disabled with the tooltip "Select at least one microphone." until a cell is ticked. Whitacre shows three group rows, Core (Close, Tree, Ambient, Outriggers), Auxiliary (Mid, Gallery) and Stereo (Big, Medium, Small); CL02-CL05 and ST04 are not shown. Nothing is written until you apply.
9. Library artwork (GUI). The picture is the big one at the top left of the window and follows the profile; the library's own tiny `MST_Artwork.png` is no longer used. Without the Spitfire cache below, neither profile shows a picture until the download below arrives (the slot is empty). When the Spitfire app has cached the product picture (`~/Music/Spitfire Audio/Settings/.ImageCache/`, see `docs/SPITFIRE-SYSTEM.md`), the big picture is that official pack shot instead (BBCSO Professional violin picture, Whitacre pack shot), also before a library is chosen; without it, the downloaded public pack shot (next check) or nothing. Nothing is written to that cache folder.

9b. Downloaded picture (GUI). Launch with no Spitfire cache (e.g. `HOME` pointing at an empty folder, or the cache moved aside) and File > Download Profile Pictures checked (the default): after a moment the 500x500 pack shot of the active profile appears (BBCSO Professional, Eric Whitacre Choir after switching), hovering shows `Picture: https://www.spitfireaudio.com/...`, and a ~30 KB file named by a 40-character hex name exists in `<app data dir>/ImageCache`. Quit and relaunch offline: the picture still shows. Uncheck File > Download Profile Pictures, delete that folder, relaunch: no picture is downloaded (the slot stays empty for both profiles). Re-checking the item downloads at once.
10. `.smtprofile` is a package. `plutil -p "<app>/Contents/Info.plist"` lists `UTExportedTypeDeclarations` with `name.mbishop.smtprofile`; in Finder the `.smtprofile` folders inside the app (`Contents/Resources/Profiles/`) show as single files ("Spitfire Mic Manager Profile") and Show Package Contents opens them. If Finder still shows a plain folder, run the app once from where it will live (launch services registers the type then).

## Whitacre real-data trial

Run this once after any change to the Whitacre profile or the classifier. Use a new folder on a local disk as the destination. Quit the plugin and its DAW first. Do NOT set `SMT_APP_DATA_DIR`.

1. Analyze. `mictrim --profile ewc -s "<full Whitacre library>" analyze`. Expect the first line to name the Eric Whitacre Choir profile, the nine offered mics (Close, Tree, Ambient, Outriggers, Mid, Gallery, Big, Medium, Small) in the groups Sopranos, Altos, Tenors, Bass and Tutti, and CL02, CL03, CL04, CL05 and ST04 listed as unknown mic codes (kept, never removed: they are not offered and always copied), no "missing from disk" line (the DB container names map to files on disk), and `ERICW_VERB_IR.spitfire` not listed as a mic; the "sample files match no mic/group" line reports at most `ERICW_VERB_IR.spitfire` (or is absent: the line counts only files listed in a database).
2. Create the destination. `mkdir -p "$HOME/SmtTrial/Spitfire Audio - Eric Whitacre Choir"` (a different local parent; the folder name must equal the source's, or the Spitfire app rejects it and `smt` refuses). It must be empty.
3. Write a "Close and Tree only" `project.smt` (no mic is locked; missing entries mean "on", so every other offered mic needs an explicit `false`; CL02-CL05 and ST04 are not in the file and are always copied):

```
python3 - <<'EOF'
import json, os
dest = os.path.expanduser("~/SmtTrial/Spitfire Audio - Eric Whitacre Choir")
keep = {"cl01", "tr01"}
mics = "cl01 tr01 am01 ou01 mi01 ga01 st01 st02 st03".split()
groups = "sopranos altos tenors bass tutti".split()
json.dump({"profile": "name.mbishop.smtprofile.ewc",
           "micSignals": {m: {g: m in keep for g in groups} for m in mics}},
          open(dest + "/project.smt", "w"))
EOF
```

   (Or use the GUI: Whitacre source, that destination, tick Close and Tree in the Core group for every voice column, and apply from the plan dialog. Apply stays disabled while no mic is ticked.)

4. Plan. `mictrim --profile ewc -s "<source>" -p "<dest>" plan`. Expect no file of a switched-off mic to be copied (Patches, Presets, NKS, `ERICW_VERB_IR.spitfire` and the unknown-code files are copied too: all CL02-CL05 and ST04 files, about 7.4 + 7.7 + 7.7 + 7.2 + 6.0 GB = ~36 GB, because they are always included), a patched `ERICWCHOIR_FULL.db` (check its rebuild line keeps roughly the number of files you expect), no refusals, and a byte total of roughly 36 GB plus Close and Tree, far below the source's 153 GB.
5. Apply. `mictrim --profile ewc -s "<source>" -p "<dest>" apply -y`. Expect it to finish; run `plan` again: nothing left to do.
6. Repair the SOURCE. In the Spitfire app, Repair Eric Whitacre Choir (and Evo Grid) on the source library before step 5, not on `<dest>`: Repair re-signs `Patches`/`Presets`/`Config` in place and Apply copies them (see "Patches after Repair"). Then point the plugin at `<dest>` with "Change current installation location…".
7. Load a Sopranos patch in the plugin. Expect sound (Close, Tree and the always-copied CL02-CL05/ST04), and a red exclamation mark whose dialog is "Error #4" (cannot locate samples): that is the removed mics, which stay listed but have no samples. Enabling the plugin's "disable missing samples" setting (`defaultIgnoreMissingSamples`, per library under `~/Music/Spitfire Audio/Settings/`) should clear it. If the plugin refuses to load or plays nothing, stop, do not trim further, and record it in `docs/SPITFIRE-SYSTEM.md` sections 5 and 8.
8. Record the outcome in `docs/SPITFIRE-SYSTEM.md` (Whitacre behaviour), run `mictrim -s "<full Whitacre library>" -p "$HOME/SmtTrial/Spitfire Audio - Eric Whitacre Choir" use source`. `use source` points the Whitacre entries at the full library again; this is not a restore, and delete `~/SmtTrial`.

Afterwards, point `Spitfire.properties` back at the real library.

**Plugin notes.** Point the plugin at the trimmed copy with "Change current installation location…" (it only rewrites `Spitfire.properties`/`lm.conf`; the copied `.spitfire` files need no re-authorisation). The plugin then shows a red exclamation mark whose dialog is "Error #4" (cannot locate samples): that is the removed mic positions, which stay listed (from the encrypted `.zmulti`) but have no samples; Mix 1 loads and plays. Its settings have `defaultIgnoreMissingSamples` (per library, in `~/Music/Spitfire Audio/Settings/BBC Symphony Orchestra.settings`).

**Patches after Repair.** Run Spitfire's Repair on the SOURCE library first (it rewrites `Patches`, `Presets` and `Config` in place at the same size), then Apply to the destination (the button shows the refreshed bytes even when nothing else changed), point the plugin at the destination with "Change current installation location…" and load a patch: it must load without "failed to load patch config" (Error #1). Apply again after a new Repair: the patches are replaced again.

**Switching libraries.** With the DAW closed run `mictrim -s <src> -p <dest> use trimmed` (or "Change current installation location…" under the profile picture in the GUI), check `~/Music/Spitfire Audio/Settings/Spitfire.properties` now lists `<dest>/Config`, `/Patches`, `/Presets`, `/Samples` for the BBC entry, wherever it pointed before (a `.smt-backup` sits next to it, other products untouched; for Whitacre the three entries "Eric Whitacre Choir", "... Evo Grid" and "... Samples" with their sub-paths); the GUI message names the entries and the folder, load the plugin; then `mictrim -s <src> -p <dest> use source` and check it points at the original again. No Repair needed.

## Checked mics follow the Reduced Mic Installation (GUI)

The matrix (rows = microphones, columns = sections, one group row per family group, sizes in every cell, a row total at the right and each column's selected total under its heading) always shows what is complete on disk in the Reduced Mic Installation; `project.smt` does not decide them (the CLI still uses it).

1. Choose the source and an empty (or new) Reduced Mic Installation folder. Expect no cell filled, except BBCSO's locked Mix 1, which is grey (always on, not clickable) (Whitacre has no locked mic: nothing filled and Apply disabled until one is chosen).
2. Tick one mic, Plan, Apply. When the destination rescan ends, expect that mic's cells filled for exactly the sections that were copied, and all others not filled.
3. Interrupt an apply (Cancel, or quit) while a mic is being copied and reopen the app on the same folders. Expect that mic's cell amber, "<size> partly present" (tooltip: only partly present; Apply will complete it; untick to remove it). Apply again: the plan copies the missing files and deletes nothing, and the cell turns the normal filled colour. Instead, click the amber cell once: it becomes not filled and the plan then deletes that mic's files from the Reduced Mic Installation; click again: filled.
4. Switch the profile or the Reduced Mic Installation folder: no box keeps a stale checked state from the previous one.
4b. Choosing the destination (GUI). With a `Spitfire Audio - <product>` source chosen, pick any other folder with "Choose…" under Reduced Mic Installation: the path shown is that folder plus `/Spitfire Audio - <product>` and nothing is created yet (Apply creates it; a refused or cancelled run leaves the folder you picked untouched). Pick a folder that already has the exact name: it is used as it is. Pick the source's own parent folder: the path becomes the source and Apply stays greyed with "The destination is the same folder as the source." beside it. On the command line `-p` is used literally and a wrongly named folder is refused.

5. Matrix controls. One matrix, no tabs; group rows (BBCSO: Mixes, CTAO, Stereo/Mono, Spills, Other, Atmos; Whitacre: Core, Auxiliary, Stereo) span the width. Cells have no checkboxes: the whole app is dark (near-black window, grey text, white headings, blue accent) whatever the macOS appearance: a blue tile with dark text = included, a dark tile with light text = not included, amber = partly present ("<size> partly present"), grey = always on; the heading of a column is blue when all its mics are wanted, a damped blue when some are and dark when none. Clicking anywhere in a cell toggles it and the row total and column total follow. A row's name cell and a column heading (tooltip "Click to toggle the whole column") work alike: fully filled/tinted (everything wanted, partly present included) a click clears all; lighter (some off) a click fills the missing ones and leaves partly present cells as they are (column: unlocked mics only); the arrow keys move cell to cell and Space toggles the current cell; locked mics are greyed ("always on") and unaffected. A partly present cell reads "<size> partly present" with the tooltip; the Apply button is disabled while nothing is ticked. Directly below the matrix, right-aligned so it ends under the Row total column's numbers (also with the scrollbar shown), one line reads "Installation size: X (Y space remaining)": X is what the Reduced Mic Installation will contain, including the files that are always copied (databases, patches, impulse responses; hover for the tooltip), Y the free space that will be left on the destination after Apply. Without a destination it reads just "Installation size: X"; when the destination is too small it reads "Installation size: X (Needs Z more space)" in red. The size of the full library is not shown. Apply shows the pending change on the blue primary button ("Apply (+X / −Y)": bytes to copy / to delete) "Apply (update databases)" when only database rebuilds remain (they also resume an interrupted apply), and "No changes" (greyed) only when the plan has no step at all. Apply is greyed, with the first refusal written in red to its left (and as its tooltip), when the plan cannot run (overlap, name mismatch, lock, configuration error, no destination, not enough space). Below the matrix a legend names the tile colours. With no source chosen (or an empty one) a hint "Choose a Source Installation to begin" replaces the matrix, legend and footer. Each folder path is plain text ("No folder chosen" until set). The window title ends with the profile name. The current cell has a white outer and a dark inner outline, visible on light, amber and dark tiles.
